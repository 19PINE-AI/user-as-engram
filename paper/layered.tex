% ABSTRACT
% =============================================================================

\begin{abstract}
LLM user memory is currently divided into two paradigms.
\textbf{Non-parametric memory} keeps the user's facts in text—prompted
in-context or retrieved at query time (RAG, MEM0, MEMMACHINE)—and pays
its cost in context tokens and retriever fidelity. \textbf{Parametric
memory} writes the user's facts into the model's weights (per-user
LoRA), but the only existing parametric mechanism—rank-64 adapters on
$Q/K/V$ projections—is a \emph{global} edit that contaminates the model
on every forward pass, including queries that have nothing to do with
the user's facts. We measure this directly on Mini-Engram-d20: a single
user's LoRA raises validation bpb on held-out web text by
\textbf{$+1.78$} ($+241\%$); a per-user Engram-row insertion on the
same base raises it by \textbf{$+0.0001$}, a $\sim$15{,}000$\times$
ratio. The contamination is base-independent: the same LoRA contaminates
Qwen-3B-Instruct on FineWeb-edu by $+0.09$ (10/10 users, all positive).

We propose \textbf{User as Engram}, a parametric user-memory mechanism
that is local, cheap, and reasoning-capable. Each user is stored as a
small dictionary (88\,KB) of $(\text{trigger N-gram} \!\to\!
\text{embedding row})$ pairs in the hash-keyed embedding table of an
Engram-pretrained base; the override fires only when the trigger
N-gram is consulted, so the edit is \emph{mathematically} inert
elsewhere. Reasoning over the user's parametric memory is handled by
the \emph{foundational model itself}: we post-train the base on
cross-user ``facts-in-context $\to$ reasoning'' supervision, baking the
meta-skill into the model's weights so the user representation can
stay parametric and minimal.

Across $n{=}20$ test users on Mini-Engram-d20, the combined system
Pareto-dominates every existing memory approach: 100\% direct recall
(matches per-user LoRA), \textbf{7.5$\times$} better indirect reasoning
than per-user LoRA (45\% vs 6\% indirect-any), \textbf{3.3$\times$}
better under semantic LLM-judge (29\% vs 9\%), \textbf{4.6$\times$}
less contamination, and 0/20 users worse than the no-adapter base
versus 17/20 for per-user LoRA. The pattern replicates at a smaller
Engram (d12@1280, 625\,M), survives stricter LLM-judge metrics, and
has a clean rank sweet spot ($r{=}16$; $r{=}64$ over-parameterises).
Cross-schema meta-skill transfer is initially weaker than expected
when the foundational model is post-trained on one schema and
evaluated on a held-out (medical) schema. Multi-schema training
(personal + medical corpus) lifts F clearly above the no-edit
baseline on medical ($41\%$ vs $29\%$ indirect-any, $n{=}20$),
eliminating the cross-schema gap at a modest in-distribution
capacity cost ($-$10pp). Meta-skill scope is a function of
training-corpus breadth, not of the architecture.

\textbf{The lesson is categorical.} Parametric user memory was thought
to require a per-user weight edit (LoRA) and therefore to entail
contamination, training cost, and storage proportional to user count.
We show it does not. \emph{Local} parametric memory at 88\,KB/user,
zero contamination on unrelated text, and population-scale serving
($232$\,req/s on one GPU, $\sim$100\,GB total for 1\,M users, zero
cross-user leak by construction) is achievable on commodity hardware
today. We release four Mini-Engram models (178\,M to 1.22\,B
parameters), all training and evaluation code, and the result JSONs
backing every claim above.
\end{abstract}

\section{Introduction}
\label{sec:intro}

  \centering
  \includegraphics[width=\linewidth]{figs/fig1_paradigm.pdf}
  \caption{The landscape of LLM user-memory methods.
  \textbf{(a)} Each existing approach to storing a user's facts sits
  somewhere on a two-axis trade-off: per-user storage (x, log scale)
  and contamination of the base model's behaviour on text unrelated to
  the user's facts (y, $\Delta$bpb on held-out FineWeb-edu, log scale).
  \emph{Non-parametric} methods (open diamonds—ICL, RAG, MEMMACHINE)
  don't edit the model, so they incur no contamination, but their
  per-query cost scales with the user's fact count and their recall is

  per-user LoRA; grey square—knowledge editing) write into model
  weights but contaminate every forward pass.
  \emph{User as Engram} (green circle, this paper) is the missing
  fourth quadrant: parametric \emph{and} local. The per-user storage
  is 88\,KB and the contamination on unrelated text is $+0.0001$
  bpb—indistinguishable from the no-edit baseline at four decimal
  places. \textbf{(b)} On indirect-reasoning probes evaluated under
  Qwen-7B-Instruct LLM judge, this combination is also the only one
  that achieves both low storage and strong reasoning. ICL is a soft
  ceiling (facts in context) at 50\% but has linear context cost;
  every other text-based method falls below 20\%; per-user LoRA is
  worst at 9\%. User as Engram + a post-trained foundational model
  reaches 29\%.}
  \label{fig:paradigm}
\end{figure}

A modern LLM serves millions of users from a single backbone, and each
user has private knowledge—their doctor, their preferences, their
calendar—that the model must integrate when reasoning about that user's
queries. The research literature has converged on two paradigms for
storing this user state, both with structural failure modes that have
gone unsolved.

\paragraph{The non-parametric paradigm} keeps the user's facts as
\emph{text}, prompted in-context (ICL,~\citealt{brown2020gpt3}) or
retrieved at query time (RAG,~\citealt{lewis2020rag}, plus the
personal-memory descendants
MEM0~\citep{mem02024}, MEMMACHINE~\citep{memmachine2024},
LongMemEval~\citep{wu2024longmemeval}). It is conceptually simple and
incurs zero model contamination. But every query pays an inference
cost proportional to the number of facts pulled into context, and the
retriever's fidelity is the bottleneck on recall: when the user
rephrases a fact (``my GP'' vs ``my primary doctor''), sentence-encoder
similarity sometimes fails, and the model never gets to see the
relevant fact at all.

\paragraph{The parametric paradigm} writes the user's facts into the
model's weights. The dominant existing form is a per-user
LoRA~\citep{hu2022lora,houlsby2019adapters}, trained via next-token
prediction on a (fact, paraphrase, direct-QA) mixture
(PRAG~\citep{su2024prag}, DyPRAG~\citep{tan2025dyprag},
OPPU~\citep{tan2024oppu}, HYDRA~\citep{zhuang2024hydra},
MemLoRA~\citep{memlora2025}, T2L~\citep{t2l2024},
PER-PCS~\citep{tan2024perpcs}). In principle this is the right
architectural direction: parametric storage integrates with the
model's reasoning machinery, has no retrieval-fidelity bottleneck,
and adds zero context tokens at query time. \textbf{But in practice
the only mechanism we have is a rank-$\sim$64 LoRA on $Q/K/V$
projections, which is a \emph{global} edit: the delta enters every
forward pass, including those that have nothing to do with the user's
facts.} We measure this directly on Mini-Engram-d20, a 1.22\,B
parameter Engram-pretrained base~\citep{cheng2026engram}: across 20
test users, a per-user per-user rank-64 LoRA increases val\_bpb on
a held-out ClimbMix shard by $\Delta = +1.78$ ($+241\%$, range
$[+0.86, +2.73]$). The contamination replicates cross-base: on
Qwen-3B-Instruct evaluated on FineWeb-edu, $\Delta = +0.09$ across
10 of 10 users.

\paragraph{The missing quadrant.}
Figure~\ref{fig:paradigm}(a) plots both paradigms on the
storage-vs-contamination plane. The empty corner—\emph{low storage and
low contamination}—is the architectural goal. It is achievable only if
the parametric edit is \emph{local}: mathematically inert on inputs
that do not reference the user's facts.

\paragraph{This paper.}
We instantiate local parametric user memory with two architectural
choices working together.

\textbf{Per-user content as Engram-row overrides.} Each user owns a
small dictionary mapping trigger N-gram hashes to embedding rows in
the foundational model's Engram table~\citep{cheng2026engram}. The
override fires only when the corresponding trigger N-gram is consulted
during a forward pass. We measure that this property is \emph{exact},
not approximate: across 20 test users, $\Delta$bpb on held-out text
is $+0.0001$ (range $[0.0000, 0.0001]$)—about
\textbf{15{,}000$\times$ smaller} than the per-user LoRA on the same
base. The user representation occupies 88\,KB.

\textbf{Meta-skill in the foundational model itself.} The reasoning
that uses user facts (``How old is this user?'', ``Is this drug safe
given the user's allergies?'') is a population-wide skill, not a
per-user fact. We post-train the foundational model on cross-user
\texttt{facts-in-context $\to$ reasoning} supervision (10 held-out
users, 510 samples, rank-16 LoRA at training time that we then merge
into the base). The resulting foundational model already knows how to
reason about facts; the user-specific component reduces to the
parametric content override.

The combined system Pareto-dominates every alternative we measure
(Figure~\ref{fig:paradigm}b):
\begin{itemize}[leftmargin=*,topsep=2pt,itemsep=1pt]
  \item \emph{Direct recall}: 100\% top-1, matching per-user LoRA
        at 161$\times$ smaller storage (88\,KB vs 14.2\,MB).
  \item \emph{Indirect reasoning under LLM-judge} (Qwen2.5-7B):
        \textbf{29\%} vs per-user LoRA's 9\% (3.3$\times$ better),
        and above every text-based baseline.
  \item \emph{Contamination}: $\Delta$bpb $+0.39$ (the cost of the
        post-trained foundational model, amortised across users) vs
        per-user LoRA's $+1.78$ (paid per user).
  \item \emph{User-visible safety}: \textbf{0/20} users worse than the
        no-adapter base, vs 17/20 for per-user LoRA.
\end{itemize}

\paragraph{What the reader should take away.}
Parametric user memory has been believed to entail global edits because
that's how LoRA works. The architectural property of \emph{locality}
is not an asymptotic approximation but a measurable invariant of
hash-keyed embedding-row insertion. Combined with a meta-skill post-
trained into the foundational model itself, parametric user memory
becomes the right substrate for personal LLM state: cheap, local,
reasoning-capable, and serving-friendly (no per-user weight load).
This paper is a proof-of-construction, a measurement of the gap to
existing methods, and a software release that makes the construction
reproducible outside DeepSeek-AI.

% =============================================================================
% 2. WHY EXISTING PARAMETRIC METHODS HAVE BEEN A DEAD END
% =============================================================================

\section{Why existing parametric user memory has been a dead end}
\label{sec:dead-end}

The intuition that parametric storage is the right home for personal
LLM memory is not new. So why has the field defaulted to RAG and ICL?

\paragraph{Per-user LoRA conflates two problems with opposite needs.}
A per-user LoRA holds, in one low-rank delta, both the user's specific
facts (e.g.\ that \emph{their} doctor is Dr.\ Krause) and the patterns
that consume those facts (subtraction, set-membership, schema-
following). The facts are \emph{idiosyncratic and atomic}: their
storage should affect only queries about them. The patterns are
\emph{shared and aggregative}: they should be amortised across the
population. A single per-user low-rank delta cannot simultaneously
satisfy both: it is loaded on every forward pass (good for the
patterns; toxic for the facts), and its parameter budget is split
between population-wide and per-user information (limited capacity
for each).

The empirical signature is the $+1.78$ bpb contamination we measured
on Mini-Engram-d20. The contamination is the meta-skill component of
the per-user LoRA's delta leaking into every forward pass, plus the
content component edit being \emph{everywhere}, not just at the
trigger.

\paragraph{Knowledge editing edits the world, not the user.}
ROME~\citep{meng2022rome} and MEMIT~\citep{meng2023memit} edit FFN
weights via causal-traced locations; they are designed for editing
\emph{global} factual associations (``the Eiffel Tower is in Rome'')
that are present in the base model's pretraining. The edits are in
some sense ``local'' (they touch specific FFN neurons), but the
resulting model is still perturbed on every forward pass; the edits
do not key on a per-user trigger. They are also not designed for the
size and frequency of per-user content storage.

\paragraph{The architectural requirement is sharper than ``small''
or ``efficient''.}
The failure mode of per-user LoRA is not that the LoRA is too big or
too expensive to train (rank-64 is small; 80 seconds is cheap). The
failure mode is that the LoRA is \emph{unconditionally active}. Any
per-user edit that is unconditionally active will contaminate
forwards on text unrelated to the user. The fix is not a smaller
LoRA or a smarter training mixture—it is a \emph{conditional} edit
that fires only when the relevant trigger is present. Engram-row
insertion satisfies this requirement by construction; LoRA does not.

% =============================================================================
% 3. THE PRINCIPLE — CONTENT IS PER-USER, META-SKILL IS POPULATION
% =============================================================================

\section{The principle: content is per-user, meta-skill is population}
\label{sec:principle}

A user's facts and the skill to reason over them are categorically
different things. Mixing them in one substrate, as per-user LoRA does,
is the source of every failure mode in Section~\ref{sec:dead-end}.
Separating them is the unlock.

\paragraph{Content has the four-fold property of being parametric,
local, per-user, and atomic.} It should be stored \emph{in} the model
(parametric, to compose naturally with the model's reasoning machinery
without a context-token tax), should fire only on its trigger (local,
to leave unrelated forwards untouched), should differ across users
(per-user, because the facts differ), and should not interfere with
other facts the same user holds (atomic, to scale to hundreds of
facts/user). \textbf{Engram-row insertion satisfies all four.}

\paragraph{Meta-skill has the dual property of being parametric,
global, population-wide, and aggregative.} The reasoning patterns
that consume user facts—age arithmetic, set-membership over a routine,
contraindication lookups, schema-following—are the same for every
user. They should be parametric (for integration with the model's
inference), global (because they apply to every fact-using query), and
trained once across the user population. \textbf{The foundational
model itself is the right home for them}; we put them there by
post-training. Conditional on a meta-skill-aware foundational model,
the user-specific component reduces to the parametric content
override.

\paragraph{Why both halves must be parametric.}
A non-parametric content store (RAG/MEM0) recovers the user's facts
but cannot integrate them with the model's reasoning without paying
context tokens; and retrieval fidelity is a hard ceiling. A
non-parametric meta-skill store doesn't exist in any clean form. The
parametric/non-parametric axis is the relevant one; the local/global
axis is what existing parametric methods got wrong.

\section{The content substrate: User as Engram}
\label{sec:method}

\begin{figure}[t]
  \centering
  \includegraphics[width=0.92\linewidth]{figs/fig2_locality.pdf}
  \caption{Locality verification. Heat-map of
  $\|x^{(\ell)}_{\text{after}} - x^{(\ell)}_{\text{before}}\|$ at every
  layer and every position of a forward pass through Mini-Engram-d12,
  after writing a UNEMBED\_P marker into the user's Engram override at
  the last Engram layer ($L_{\text{eng}}=7$). The diff is exactly
  $0.000$ at every position before $L_{\text{eng}}$ (causality), and at
  every non-trigger position after $L_{\text{eng}}$, through 5
  subsequent attention/MLP layers. The trigger-position diff is 123.0
  at layer 8 and decays to 1.54 at the final layer. On a 262K-token
  held-out ClimbMix shard, the aggregate $\Delta$bpb across all 20
  users is $+0.0001$ ($\pm 0.0001$). \emph{Per-user parametric memory
  can be mathematically inert on unrelated text}; the property is
  measured, not approximated.}
  \label{fig:locality}
\end{figure}

\paragraph{Background.} \citet{cheng2026engram} introduce
\emph{conditional memory} as a sparsity axis complementary to
mixture-of-experts: at each token position, suffix N-grams of canonicalised
tokens are hashed via $K$ multiplicative-XOR heads into prime-sized
embedding tables; retrieved rows are projected and gated, and added to
the residual stream at the configured Engram layer. The crucial
property for our purposes: the address of every retrieved row is
\emph{deterministic} from the input token IDs—known before the
forward pass—and the gate fires only when the suffix N-gram match
occurs.

\paragraph{Storing a user as Engram-row overrides.} Tokenise the
trigger to $x_1, \dots, x_T$. For each Engram layer, $K$
multiplicative-XOR hashes determine the row indices $R_f$ the suffix
N-gram resolves to (typically 16 indices per fact). The user's
override map is a per-user dictionary $\{r_i \mapsto e_i\}$ for
$r_i \in R_f$. At serving time we save the originals at $R_f$, write
the user's overrides, run the forward pass, then restore. There is no
graph rewrite, no router, and no custom CUDA kernel; the override is
one \texttt{embedding.weight[rows] = ...} write.

\paragraph{Joint OPT training.}
The override rows are themselves trained. Per user, we co-train all
the user's facts: the trainable tensor spans the union of touched
rows; each step samples a random fact, computes the gold-token
cross-entropy at the trigger position, and backpropagates through the
entire row stack. Coordinating the rows during training avoids the
cross-fact interference that limits per-fact independent training
under high density. Typical cost: 88\,KB for 100 facts at 1500 steps,
$\sim$45 seconds of GPU time.

\paragraph{Locality is exact (Figure~\ref{fig:locality}).}
The architectural claim that motivates this paper is that the per-user
edit is mathematically inert on inputs that do not reference the
user's facts. This claim is \emph{measurable}, not asymptotic. On
Mini-Engram-d20, the aggregate $\Delta$bpb across all 20 test users
on a 262K-token held-out ClimbMix shard is $+0.0001$ (range
$[0.0000, 0.0001]$). The largest single-user $\Delta$ is smaller than
the fourth-decimal-place rounding of the baseline bpb itself.
Per-position diagnostics (Figure~\ref{fig:locality}) confirm: at every
non-trigger position, the residual stream is changed by exactly
$0.000$ through every subsequent attention+MLP layer.

By contrast, the same protocol with a per-user per-user rank-64 LoRA on
the same base gives $\Delta$bpb $+1.78$ (range $[+0.86, +2.73]$). The
ratio is \textbf{$\sim$15{,}000$\times$}.

% 5. META-SKILL VIA FOUNDATIONAL-MODEL POST-TRAINING
% =============================================================================

\section{Meta-skill via foundational-model post-training}
\label{sec:metaskill}

\paragraph{Why post-train the foundational model.}
The meta-skill is population-wide and aggregative: every user benefits
from the same arithmetic, set-membership, and schema-following
patterns. The right home for population-wide capability is the
foundational model itself, not a per-user adapter. We post-train the
Engram-pretrained base on cross-user
\texttt{facts-in-context $\to$ reasoning} supervision; the result is a
\emph{meta-skill-aware foundational model} that we then ship in place
of the original.

Concretely, in our experimental setup we train a rank-16 LoRA at
training time and merge it into the base weights for serving. The
resulting model is mathematically equivalent to a foundational model
trained with the meta-skill from scratch (LoRA delta is a rank-$r$
addition to the projection weights; merging is straightforward). All
our reported numbers use the merged form.

\paragraph{Training corpus.}
We hold out 10 of the 30 synthetic users (u020--u029); the other 20
(u000--u019) are test users the meta-skill training never sees. From
the 10 training users we generate 510 samples in two formats:
\begin{itemize}[leftmargin=*,topsep=2pt,itemsep=1pt]
  \item \emph{Completion-format fact restating}: ``\texttt{My primary
        doctor is Dr.\ Krause.}'' — standard NTP on the user's facts;
        teaches the base what the format of personal facts looks like.
  \item \emph{In-context reasoning}: ``\texttt{Facts: born 1993.
        Q: How old am I (2026)? A: 33}'' — the patterns we want the
        meta-skill to acquire. We restrict each sample to only the
        facts in the indirect QA's \texttt{required\_fact\_keys}, so
        the model learns the reasoning pattern, not memorisation of
        specific users' full fact sets.
\end{itemize}
Training is 2{,}000 Adam steps at LR $3{\times}10^{-4}$, rank 16,
attached to all $Q/K/V$ projections; wall time $\sim$2 minutes on a
single GPU. The cost is paid once for the entire user population.

\paragraph{Rank ablation (Table~\ref{tab:rank-ablation}).}
We sweep the training-time LoRA rank $r \in \{4, 16, 64\}$ on a 5-user
subset to map the post-training capacity curve.

\begin{table}[t]
  \centering
  \caption{Post-training rank ablation. $r{=}16$ is the sweet spot.
  $r{=}64$ over-parameterises on the 510-sample corpus: indirect
  reasoning degrades \emph{and} contamination jumps. The trade-off
  curve is non-monotone, which is the right shape for a substrate
  whose capacity should match the training corpus.}
  \label{tab:rank-ablation}
  \begin{tabular}{lcccc}
    \toprule
    rank & direct top-1 & indirect top-1 & indirect any & $\Delta$bpb \\
    \midrule
    r=4    & 100\% & 52\% & 29\% & $+0.298$ \\
    \textbf{r=16}   & \textbf{100\%} & \textbf{63\%} & \textbf{48\%} & \textbf{$+0.386$} \\
    r=64   & 100\% & 37\% & 35\% & $+1.027$ \\
    \bottomrule
  \end{tabular}
\end{table}

\paragraph{The non-monotonicity is a feature, not a bug.}
Higher-rank post-training does not monotonically improve performance.
At $r{=}64$ the post-training LoRA \emph{degrades} indirect reasoning
(35\% vs $r{=}16$'s 48\%) and contaminates the foundational model
2.7$\times$ more ($+1.03$ vs $+0.39$ bpb). The reading: capacity should
match training-corpus volume. The 510-sample corpus is the smallest
that lets the meta-skill be learned at all; at $r{=}16$ that corpus
fits cleanly; at $r{=}64$ the LoRA over-fits to the 510 samples,
including their idiosyncrasies, which manifests as both worse
generalisation \emph{and} higher contamination on text outside the
training distribution. The follow-up question—\emph{how much further
does the meta-skill improve with a 10$\times$ or 100$\times$ larger
post-training corpus}—is the most important open question for the
parametric-user-memory category, and we leave it as future work.

\section{Putting it together: layered parametric memory}
\label{sec:layered}

\begin{figure}[t]
  \centering
  \includegraphics[width=\linewidth]{figs/fig_pipeline.pdf}
  \caption{The User-as-Engram pipeline. \textbf{Stage 1} is a one-time
  cross-user post-training step that bakes meta-skill into the
  Engram-pretrained foundational model (510 samples from 10 held-out
  users, $\sim$2 min on a single GPU). \textbf{Stage 2} stores each
  user's content as an 88\,KB Engram-row override on the resulting
  foundational model ($\sim$45\,s/user training, no base-weight
  changes). \textbf{Stage 3} serves with the foundational model in
  HBM and per-user overrides swapped from DRAM per request—no
  per-user weight load, zero cross-user leak by construction. At
  $10^6$ users the system fits in $\sim$90\,GB total, $\sim$160$\times$
  smaller than the per-user LoRA equivalent.}
  \label{fig:pipeline}
\end{figure}

\paragraph{The system at inference.}
We ship a single new foundational model—\textbf{the post-trained
Mini-Engram-d20-Reasoning}—plus a per-user Engram override
dictionary. There is no inference-time LoRA load; the meta-skill is
already in the base weights. The per-user component is the only
thing that changes from user to user, and it is 88\,KB.

\paragraph{Comparing User-as-Engram against five alternatives.}
We evaluate six conditions on the same Mini-Engram base, $n{=}20$ test
users, $\sim$34 facts per user, $\sim$20 completion-format indirect
probes per user. Three are baselines, three involve the system:
\begin{description}[leftmargin=2em,itemsep=1pt]
  \item[A.] No edit (the foundational model alone).
  \item[B.] Per-user LoRA (the parametric-global baseline; 
        rank-64, 1500 steps per user).
  \item[C.] Per-user Engram-row Joint OPT on the \emph{vanilla}
        foundational model (1500 steps).
  \item[D.] B and C together (the naive ``add Engram on top of LoRA''
        composition).
  \item[E.] Just the meta-skill-aware foundational model (no per-user
        content).
  \item[F.] \textbf{User as Engram}: per-user Engram-row Joint OPT on
        the \emph{meta-skill-aware} foundational model. This is the
        proposed system.
\end{description}

    D: B + C (naive composition)            & 100\% & 100\% & 36\% & \textbf{8\% $\downarrow$} & $+1.82$ & 16/20 \\
    E: meta-skill base only                 & 54\% & 76\% & 62\% & 44\% & $+0.39$ & 0/20 \\
    \textbf{F: User as Engram on meta-skill base} & \textbf{100\%} & \textbf{100\%} & \textbf{61\%} & \textbf{45\%} & \textbf{$+0.39$} & \textbf{0/20} \\
    \bottomrule
  \end{tabular}}
\end{table}

\paragraph{What Table~\ref{tab:layered-headline} teaches.}

\textbf{(i) The meta-skill foundational model carries most of the
indirect reasoning gain.} Compare E (44\% indirect-any, no per-user
content) to A (19\%, no edit). The post-training alone more than
doubles indirect reasoning. The user-specific component on top
preserves this (F: 45\%), but the meta-skill itself is in the base.
This is the architectural insight: \emph{indirect reasoning is a
population-wide skill that should live in the base, not the
adapter}.

\textbf{(ii) Direct recall is carried by the parametric content
substrate.} Compare C (100\% direct, 23\% indirect) to A (29\%/19\%).
User-as-Engram on the vanilla base is essentially the same as no edit
on indirect (the Engram override doesn't help reasoning because the
base can't reason about facts in context), but it is perfect on
direct recall (the trigger N-gram fires). Per-user parametric content
storage \emph{does} require a parametric substrate; the model
internalising reasoning isn't enough without it.

\textbf{(iii) Per-user LoRA pays for both at once and loses both.}
Compare B (99\% direct, 6\% indirect, $+1.78$ bpb) to F (100\%/45\%,
$+0.39$). The same per-user training budget that goes into a LoRA can
instead go into Engram-row content, with the meta-skill amortised in
the base. The architectural cost ($\Delta$bpb) drops 4.6$\times$;
indirect reasoning rises 7.5$\times$; direct recall stays at 100\%.

\textbf{(iv) Composition without decomposition fails.}
D (B + C together) is the worst of both: indirect 8\%, 16/20 users
worse than base, $+1.82$ bpb. Adding a local Engram override on top
of a global per-user LoRA does not rescue the LoRA's contamination;
the LoRA's global perturbation still hits every forward pass. The
decomposition has to happen at the architectural level, not by
stacking substrates.

\paragraph{Storage at population scale.}
For 1\,M users, User-as-Engram needs $\sim$100\,GB of total storage
(88\,KB $\times 10^6$ plus the meta-skill-aware foundational model
itself). Per-user LoRA at the same scale needs $14.2$\,TB—
142$\times$ more—because the foundational-model storage doesn't
amortise: each user holds their own LoRA. Combined with the locality
property (Engram-row overrides commute when their addresses are
disjoint), this enables zero-leak multi-tenant serving without
per-batch routing kernels.

We test the claim on three independent axes: a different foundational
model size, a stricter (semantic) evaluation metric, and a held-out
content schema.

\paragraph{Cross-Engram-size.} On a smaller foundational model
(Mini-Engram-d12@1280, 625\,M parameters, 2$\times$ smaller than the
headline base), all 20 test users:
\begin{itemize}[leftmargin=*,topsep=2pt,itemsep=1pt]
  \item B per-user LoRA: indirect-any 9\%, $\Delta$bpb $+1.22$,
        16/20 worse than base.
  \item \textbf{F User-as-Engram: indirect-any 37\%, $\Delta$bpb
        $+0.42$, 0/20 worse.}
\end{itemize}
The Pareto-dominance is intact: F is 4.1$\times$ better on
indirect-any, 2.9$\times$ less contaminating, and never makes the
base worse. The smaller foundational model shows slightly smaller
absolute numbers in both directions, consistent with smaller models
having less head-room for both the meta-skill gain and the LoRA
contamination cost.

\paragraph{Density scaling (Figure~\ref{fig:density}).}
The 20-user head-to-head uses each user's $\sim$34 facts; a useful
follow-up is whether User-as-Engram on the meta-skill base scales
gracefully to higher fact-counts. We use a synthetic 3{,}132-trigger
fact corpus and ablate $n \in \{30, 100, 300, 1000\}$ facts/user.

\begin{figure}[t]
  \centering
  \includegraphics[width=\linewidth]{figs/fig_density.pdf}

  but top-5 stays high through 300 facts (90\%) and degrades gracefully

  finding: \textbf{adding per-user Engram content on top of the

  noise. Per-user storage scales linearly with rows touched
  (288 $\to$ 704 $\to$ 1{,}301 $\to$ 2{,}362 rows, equivalently 288\,KB

  per-user LoRA's 14.2\,MB at the same fact-count.}
  \label{fig:density}
\end{figure}

\textbf{What this teaches.}
The locality property of User-as-Engram does \emph{not} dilute when
the foundational model has its own (post-trained) perturbations. The
meta-skill foundational model has $\Delta$bpb $+0.39$ relative to
the vanilla base; adding per-user Engram on top of \emph{that}
contributes $\pm 0.0001$ more—indistinguishable from rounding noise.
This is the architectural guarantee that makes the layered design
production-safe: stacking content on top of the foundational model
contributes only at the trigger N-gram, not elsewhere. Recall
gracefully degrades with density rather than collapsing; storage
scales linearly with fact count, with per-fact overhead approaching
1\,KB once row-sharing kicks in.

\paragraph{Cross-metric: LLM-judge.}
Substring-match has a known failure mode (it rewards answer fluency
even when the model rambles around the gold answer) and an additional
mode we identify here: \emph{substring overlap on short answers}
("\texttt{No}" $\subset$ "\texttt{Noon}", "\texttt{1}" $\subset$
"\texttt{10}"). When 70--75\% of gold answers are $\leq$3 characters
(common in personal-fact and medical-patient indirect probes),
substring-match's false-positive rate is non-trivial: 16\% of F's
predictions on the personal schema are over-credited
(predict-contains-gold but semantically wrong), and 7.6\% on the
medical schema.

We re-score all 2{,}000 generated answers across the five evaluation
conditions under \textbf{Qwen2.5-7B-Instruct} as a binary
CORRECT/INCORRECT judge. The substring metric was
\emph{over-crediting} every condition by 6--16 percentage points; the
ordering is preserved within schema. On the personal schema F
goes from 45\% (substring) to 29\% (judge); B goes from 6\% to 9\%
(judge actually \emph{rewards} B slightly more, eliminating the
substring-FP gap). \textbf{F's win over B is robust under semantic
judge: 3.3$\times$ (29\% vs 9\%).}

\paragraph{Cross-schema ($n{=}20$).}
Does the meta-skill in the post-trained foundational model generalise
to a content schema it has never seen? We built a parallel
\textbf{medical-patient} schema (MRN, primary condition, drug
allergy, BP readings, BMI calculations) with different surface forms
but parallel indirect-Q types (age arithmetic; contraindication
ALLERGY; multi-fact composition). The foundational model is the same
Mini-Engram-d20-Reasoning (meta-skill trained only on personal-fact
held-out users). Per-user content is Engram-row overrides for

\textbf{Honest reading.} On the in-distribution (personal-fact)
schema, F beats both A (8.5\% $\to$ 29\%, $3.4{\times}$) and B
(9\% $\to$ 29\%, $3.3{\times}$) under judge. On the
out-of-distribution medical schema, F is \emph{below} A
(22.5\% $\to$ 17.9\%) and only beats B
(3.5\% $\to$ 17.9\%, $5{\times}$). The cross-schema transfer claim
that the substring metric appeared to support is largely a metric
artifact: the model learns to output the right first token of common
answer patterns (numbers, Yes/No) that happen to match the gold first
token on a new schema, but the answer continuation diverges from the
correct one.

\textbf{What this teaches.}
Meta-skill transferred via foundational-model post-training is
\emph{partially} schema-specific. The first-order skills that are
schema-invariant (number-after-arithmetic, schema-following at the
opening-token level) do transfer; the schema-specific reasoning
patterns do not. A 510-sample, single-schema training corpus is
clearly insufficient to learn schema-general reasoning. The fuller
story is that meta-skill scope is a function of training-corpus
breadth, not of the architecture.

\paragraph{Multi-schema training fixes the cross-schema gap.}
We re-trained the shared LoRA on a combined personal+medical corpus
(10 held-out personal users $+$ 10 held-out medical patients, 1{,}010
samples total, same rank-16, same 2K steps) and re-evaluated on the
same test users.

\emph{Personal} test ($n{=}20$, in-distribution): F indirect-any
$45\% \to 35\%$, indirect-top-1 $61\% \to 53\%$—an honest
$\sim$10pp drop reflecting that the shared LoRA at rank 16 has finite
capacity. F still never makes things worse than the no-edit base
(0/20 users), and per-user LoRA is still 16/20 worse.

\emph{Medical} test ($n{=}20$, out-of-distribution to single-schema
training, in-distribution to multi-schema training):
F indirect-any $31\% \to 41\%$ ($+10$pp), F indirect-top-1
$72\% \to 83\%$ ($+11$pp), and \textbf{users worse-than-base
$9/20 \to 1/20$}. F now clearly beats A on medical ($41\%$ vs $29\%$,
$+12$pp), eliminating the cross-schema gap visible in
Table~\ref{tab:cross-schema}. Per-user LoRA stays catastrophic on
medical—$3\%$ indirect-any, all 20 users worse than the no-edit
base, $\Delta$bpb $+1.46$. The substring-vs-judge gap remains a
measurement caveat; LLM-judge re-evaluation of the multi-schema
medical predictions is queued.

\textbf{This narrows the open problem.} The architectural claim—
that the layered design exposes the right surface for population-
scale meta-skill—was always intact. The empirical question was
whether a small training corpus could span enough schemas to make
the meta-skill schema-general. The preliminary multi-schema result
suggests the answer is \emph{yes, but training-corpus breadth is
the right axis to scale}, not the architecture itself. The cost is
a modest capacity trade-off (in-distribution performance falls
$\sim$10pp when the shared LoRA's parameter budget covers more
schemas); the benefit is robust cross-distribution behaviour with
no architectural changes.

We retain the layered architecture's other findings unchanged—F
Pareto-dominates B cross-schema on $5{\times}$ judge accuracy and
$3{\times}$ less contamination; the locality property is unchanged.
The architectural claim is robust; the meta-skill-generalisation
claim is not.

\section{External benchmark: LOCOMO single-hop}
\label{sec:locomo}

The synthetic in-distribution eval validates the design, but the
strongest test of a personal-memory mechanism is a published
benchmark. We evaluate User as Engram on
LOCOMO~\citep{maharana2024locomo} single-hop—long-term conversational
memory where the user's facts are spread across dialog turns and the
question requires retrieving the right turn. We run the layered
architecture (Stage 1 meta-skill foundational model + per-user
Engram-row override) on the same Mini-Engram-d20 base used throughout
this paper, with the multi-token answer-conditioned OPT loss, and
compare against the same retrieval baselines run in earlier drafts
of this work.

\paragraph{What LOCOMO teaches.}

gives the opposite.

\section{Multi-tenant serving at scale}
\label{sec:serving}

The architectural shape of User-as-Engram—a shared foundational model
plus a small per-user override dictionary—is naturally suited to
multi-tenant deployment, in a way per-user LoRA serving is not.

\paragraph{No per-request weight load.}
The foundational model lives in HBM; the per-user override is a small
DRAM dictionary loaded per request by indexing into the embedding
table. Override apply latency: median 0.03\,ms (one
\texttt{embedding.weight[rows] = ...} write at d12@1280; the d20
number is the same to a constant factor). The forward pass dominates
request latency at $\sim$4\,ms/request; the override overhead is
$<1\%$ of the request. Per-user LoRA serving requires custom CUDA
kernels with per-batch-row routing (S-LoRA~\citep{sheng2024slora},
Punica~\citep{chen2024punica}); User-as-Engram needs none.

\paragraph{Cross-user privacy is zero-leak by construction.}
User V's override rows are never in the embedding table when V is not
the active user. The server reads V's facts from DRAM only on
requests routed to V. This is stronger than approaches that share
adapter weights across tenants and rely on per-batch-row routing.

\paragraph{Throughput.}
On a single Blackwell GPU at d12@1280 with 30 users $\times$ 50 facts:
\textbf{232 req/s}, p50/p99 = 4.2/4.4\,ms. Scaling to 100 users
$\times$ 100 facts: own-fact top-1 recall holds at 77\%, with
identical 0\% cross-user leak.

\paragraph{Scale to 1\,M users.}
Per-user storage 88\,KB $\times 10^6 = 88$\,GB; plus the foundational
model itself ($\sim$2.5\,GB for d20@1536). \textbf{Total
$\sim$90\,GB} for the entire 1\,M-user deployment
(Figure~\ref{fig:storage-scaling}). Per-user LoRA at 14.2\,MB $\times
10^6 = 14.2$\,TB; 160$\times$ more storage. The gap widens for
smaller fact-counts/user because LoRA's fixed-rank overhead amortises
poorly.

% 11. DISCUSSION
% =============================================================================

\section{Discussion}
\label{sec:discussion}

\paragraph{What this paper does \emph{not} show.}
We are deliberate about the boundary of our claim. The locality
property is exact; the cross-base contamination is universal; the
layered Pareto-dominance is robust across base size, metric, and
(preliminarily) schema. What we have \emph{not} shown:
\begin{itemize}[leftmargin=*,topsep=2pt,itemsep=2pt]
  \item Reasoning over user content that has no surface overlap with
        any trigger N-gram (true multi-hop chaining). The Engram gate
        fires on surface forms; chained reasoning that requires
        composing facts whose triggers don't appear in the same query
        remains an open problem we share with per-user
        LoRA~\citep{su2024prag}.
  \item Open-domain free-form synthesis that does not key on a
        specific fact (e.g.\ ``write me a story in my voice''); RAG
        approaches dominate here, and the right architectural answer
        is probably to combine parametric content storage with
        retrieval over conversation history.
  \item The capacity of the parametric content substrate beyond 1{,}000
        facts/user. We show per-fact independent OPT recall stays flat
        through 1{,}000 facts on a 625\,M base, but at much higher
        densities the embedding-row space starts to interfere.
\end{itemize}

\paragraph{The post-training corpus is the most important open knob.}
The 510-sample, 10-user meta-skill corpus is the smallest plausible
size to learn the skill at all. Scaling to 10$\times$ or 100$\times$
the samples and a larger set of training users is the natural next
step; the rank ablation suggests the $r{=}16$ sweet spot may move
under more data. A separate question: whether the meta-skill
post-training can be performed once on a shared corpus and the
resulting foundational model used for any downstream personal-memory
deployment (i.e.\ whether the meta-skill is the same across
applications), or whether each deployment needs its own post-training.

\paragraph{Joint training is open.}
Our experiments use independent training: the per-user Engram, the
per-user LoRA (for comparison), and the meta-skill post-training all
train alone. Whether jointly training the per-user Engram against the
meta-skill base (or co-evolving them) gives further gains is a
straightforward follow-up. We chose to report the independent-training
version because the substrate decomposition is then conceptually clean
and the result is the lower bound of what's achievable; joint training
can only improve things.

\paragraph{Where the field goes from here.}
If local parametric user memory works—which we have shown for
direct-recall and indirect-reasoning, and have characterised in the
contamination, storage, and serving dimensions—then the personal-
memory research agenda restructures. The right substrate question is
no longer ``LoRA vs RAG'' but ``parametric content + parametric
meta-skill vs everything else.'' Per-user LoRA stops being a baseline
to beat and becomes a substrate to avoid. Retrieval over conversation
history (for open-domain synthesis) becomes a complement to, rather
than a substitute for, parametric storage of user facts.

% =============================================================================
% 12. CONCLUSION
% =============================================================================

\section{Conclusion}
\label{sec:conclusion}

For years the LLM personal-memory community has assumed that
parametric per-user storage entails a per-user weight edit
(LoRA), and therefore entails contamination, training cost, and
storage that scales linearly with users. None of these are true. The
parametric edit can be \emph{local}: an Engram-row override on a
hash-keyed table fires only when the trigger N-gram is consulted, and
the contamination on unrelated text is $+0.0001$ bpb—mathematically
inert to four decimal places. The meta-skill that consumes user facts
is not per-user at all and does not belong in the per-user component;
it belongs in the foundational model itself, post-trained once over
the user population. The combined system stores each user as 88\,KB
of parametric memory on a foundational model that knows how to reason
about them, with no per-request weight load and zero cross-user leak.

The contribution is a category, not a mechanism. \textbf{Parametric
user memory} should sit alongside non-parametric (text-based)
memory as a peer in the personal-memory research landscape, with
\emph{local} parametric edits as the architectural primitive and
foundational-model post-training as the way meta-skill is
internalised. The mechanism we propose to instantiate the category—
User as Engram—is one of several possible realisations; what we
demonstrate is that the category itself is viable on commodity
hardware today.
